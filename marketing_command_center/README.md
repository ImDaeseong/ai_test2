# Hermes Marketing Studio

혼자 여러 서비스를 홍보할 때, 대상·가치·신뢰·행동이 분명한 커뮤니티 글을 만들고 **올리기 전에 품질을 점검**하는 로컬 도구입니다. 채널별 게시 주소를 연결하면 본문을 복사하고 해당 화면을 바로 엽니다. 자동 게시는 하지 않습니다.

## 사용 흐름

1. **서비스 저장** — 이름과 한두 문장 설명을 저장합니다. 여러 서비스를 번갈아 쓸 수 있습니다.
2. **글 쓰기** — 올릴 곳과 대상·가치·신뢰·행동을 적고 직접 쓰거나 `AI 초안 만들기`를 누릅니다. 글은 채널마다 따로 저장됩니다.
3. **커뮤니티 연결** — 채널별 HTTPS 게시 주소를 저장한 뒤 `복사하고 커뮤니티 열기`로 수동 게시 화면에 이동합니다. 주소와 글은 이 브라우저에만 저장됩니다.
3. **점검** — 쓰는 즉시 규칙 점검이 나옵니다(무료). 원할 때 `AI 평가 받기`로 점수, 첫 줄·설득력 평가, 고칠 점, 개선안을 받습니다.
4. **올리고 기록** — `본문 복사` 후 직접 올리고 `올렸어요`를 누른 뒤 조회·반응·가입/문의 숫자를 적습니다. 어느 곳이 반응이 좋은지 요약됩니다.

그림·영상·음악을 함께 올릴 때는 `그림·영상·음악을 함께 올린다면`의 점검표를 직접 확인합니다. 미디어 품질은 AI가 판단하지 못합니다.

## 처음 열면

처음 열면 예시로 **"마사지 연습"** 서비스(무료로 마사지를 해 주는 대신 피드백을 주는 연습 상대 모집)와 6개 채널별 글이 들어 있습니다(`src/starter.js`). 모두 수정·삭제할 수 있습니다. 브라우저에 다른 내용이 저장돼 있어도 `마사지 연습 예시 불러오기` 버튼으로 다시 불러올 수 있습니다(작성 중인 글은 확인 후 덮어씀).

## 실행

Windows에서는 `start.bat`를 더블클릭합니다. 서버가 없으면 새로 띄우고, **이전 코드로 떠 있는 서버는 자동으로 종료하고 다시 띄운 뒤** 브라우저를 엽니다. 주소는 `http://127.0.0.1:4175`입니다. 직접 실행하려면:

```powershell
$keyLoader = Resolve-Path ..\..\ai_agent\keyinfo\load-keys.ps1
. $keyLoader
python serve.py
```

`OPENAI_API_KEY`는 프로세스 환경변수로만 읽으며 브라우저, 로그, 파일에 기록하지 않습니다([`.env.example`](.env.example) 참고). 키가 없어도 규칙 점검과 기록은 동작합니다. 모든 응답은 캐시하지 않도록(`no-cache`) 보내므로 코드가 바뀌어도 옛 파일이 남지 않습니다. 서버는 앱 화면 파일만 내보내고 소스·로그·문서 요청은 404로 거절합니다.

소스와 검증 문서는 공개 저장소에서 관리합니다. 실제 API 키, 로컬 로그, 브라우저 저장 데이터와 실행 캐시는 커밋하지 않습니다.

화면이 비어 있거나 동작하지 않으면 Ctrl+F5로 새로 고침하세요. 스크립트가 로드되지 않으면 화면 맨 위에 오류와 브라우저 정보가 붉은 상자로 표시됩니다.

## 점검 방식과 한계

- **규칙 점검(무료, 즉시):**
  - 수정 필요: 너무 짧음, 결과 보장 표현(`100%`, `무조건`, `보장`)
  - 권장: 길이 초과, 과장어, 근거 없는 수치, 느낌표·이모지 과다, 인사로 시작, 긴 첫 줄, 행동 유도 없음, 링크 과다, 서비스 이름 누락·반복
- **AI 평가(유료 호출 1회):** 호출마다 확인 창을 거칩니다. 기본 모델 `gpt-6-luna`, `MARKETING_OPENAI_MODEL`로 변경합니다. 요청은 저장하지 않습니다(`store: false`). AI 초안도 같은 방식의 유료 호출 1회입니다.
- 점검 통과는 최소 기준일 뿐 반응을 보장하지 않습니다. 반응이 좋았던 글은 기록으로 확인하세요.

AI 호출이 실패하면 키 오류, 요청 한도, 시간 초과, 연결 실패, 서버 오류, 빈 응답, 키 없음을 각각 다른 안내로 보여 줍니다.

## 검증

```powershell
npm test
python -m unittest discover -s tests -v
npm run validate
python scripts\smoke_lifecycle.py
npm run e2e
powershell -ExecutionPolicy Bypass -File scripts/smoke_launcher.ps1
```

- `npm test`는 `node --test tests/*.test.mjs`를 실행합니다. 규칙 점검과, 6개 채널 시작 글이 모두 점검을 통과하는지 확인합니다.
- `python -m unittest`는 AI 초안·평가 호출, 응답 해석, 실패 종류 분류를 확인합니다.
- `npm run validate`는 파일 구성을 확인하고, 제거된 기능의 용어가 문서·코드에 남아 있으면 실패합니다.
- `smoke_lifecycle.py`는 서버 시작, 보안·캐시 헤더, 비공개 파일 404, 중복 실행 거부, 키 없는 AI 호출 거부를 확인합니다.
- `npm run e2e`는 설치된 Chrome에서 첫 실행 글, 서비스 저장, 점검, AI 응답 표시(서버 응답을 흉내 낸 값), 복사, 기록, 새로고침 유지, 오류 배너, 390px 폭, 콘솔 오류를 확인합니다.
- `smoke_launcher.ps1`은 실행기의 콜드 스타트를 임시 포트에서 확인합니다.

데이터는 브라우저 `localStorage`에만 저장되므로 브라우저 데이터를 지우면 사라집니다.

## 사람 검토 HOLD

글이 실제로 설득력 있는지, 커뮤니티 규칙과 저작권·개인정보 문제가 없는지, 오프라인 만남의 안전이 확보되는지는 올리기 전에 사람이 확인합니다. 외부 계정 권한 연결, API 자동 게시, 유료 광고는 이 앱의 범위 밖입니다.

게시 전에는 [`HUMAN_REVIEW.md`](HUMAN_REVIEW.md)의 문안·커뮤니티·안전 검수표를 사용합니다. 실제 독자 반응과 커뮤니티 운영자 판단은 자동 검사로 PASS 처리하지 않습니다.
